# ECHOHEART: 아르카의 마지막 밤

모바일 우선 **3D 탑다운 액션 로그라이트**. Raw WebGL 2 로 직접 구현한 렌더러 위에서 동작하며,
설치·빌드·npm·서버 없이 `index.html` 을 더블클릭하면 바로 실행됩니다.

---

## 실행 방법

1. 완성된 `echoheart` 폴더를 엽니다.
2. `index.html` 을 더블클릭합니다.
3. 게임이 시작됩니다.

추가 설치, 명령어, 개발 서버가 전혀 필요 없습니다. 인터넷 연결도 필요 없습니다.

### 정적 호스팅 배포

`echoheart` 폴더를 그대로 웹 서버에 복사하면 끝입니다. 빌드 산출물이 따로 없으며 모든 경로가
프로젝트 내부 상대경로입니다. (GitHub Pages, S3, Netlify 등에 폴더째 업로드)

---

## 세계관

시간을 에너지로 쓰는 거대 도시 **아르카**. 도시 중앙의 시간 동력기관이 폭주하면서 모든 생명체가
같은 밤을 반복합니다. 반복될수록 주민과 기계, 건축물은 기억과 형태가 뒤틀립니다.

주인공 **리안**은 빼앗긴 심장 대신 인공 생명 장치 **잔향심장**을 지녔습니다. 리안이 죽으면 육체는
시간 파편으로 무너지지만, 잔향심장이 전투 정보와 **사망 원인**을 저장해 새 육체를 재구성합니다.

목표는 도시 중심부에서 시간을 집어삼키는 **크로노보어**를 쓰러뜨리고 최초의 심장을 되찾는 것.
사망하거나 승리하면 허브인 **잔향의 대장간**에서 다시 깨어납니다.

---

## 핵심 게임 루프

```
타이틀 → 잔향의 대장간(3D 허브) → 무기 선택 / 영구 성장 / 심연 단계
      → 런 시작 → 일반 전투 → 잔향 선택 → 다음 경로 선택(2지선다)
      → 일반전 / 엘리트 / 회복실 / 상점 / 기억의 제단  (총 6방)
      → 최종 보스(크로노보어) → 사망 또는 승리
      → 결과 정산 → 잔향 결정 지급 → 사망 적응 획득 → 허브 복귀
      → 영구 업그레이드 구매 → 더 강해진 상태로 재도전
```

한 번의 런은 7개 방(특수방 6 + 보스 1), 대략 7~12분입니다.

## 3D 렌더링 구조

외부 엔진·라이브러리 없이 **Raw WebGL 2** 렌더러를 직접 구현했습니다.

- **셰이더 3종 (GLSL ES 3.00)** — PBR 메인 / 언릿(이펙트·트레일·접지그림자·포털) / 스카이 그라디언트
- **캐릭터 입체 쉐이딩** (이번에 강화한 부분)
  - **하프램버트 랩 라이팅** — 팔·다리·몸통이 납작하지 않고 둥근 덩어리로 읽힘
  - **키 라이트(따뜻함) + 반대편 필 라이트(차가운 청색)** — 형태의 명암 방향이 생겨 부피감이 살아남
  - **바닥 바운스 라이트** — 아래쪽이 완전히 검게 죽지 않음
  - **프레넬 림 라이트(청록)** — 실루엣이 배경에서 분리되어 또렷하게 보임
  - **노멀맵 강도 1.6배** — 표면 요철이 확실히 드러남
  - 러프니스 기반 스페큘러, AO, 거리 안개, Reinhard 톤매핑, 감마 보정
- **VAO/VBO/IBO**, 깊이 테스트, 백페이스 컬링(CCW), 알파 블렌딩, 밉맵, 이방성 필터링(지원 시)
- **원근 투영 카메라** — 플레이어 뒤 위쪽 사선 시점, 부드러운 추적 + 이동 선행, 방 경계 제한,
  타격 진동(상한/모션감소 반영), 궁극기 줌
- **애니메이션** — 리지드 파트 계층(조인트) 방식, 클립 37종, 파트별 로컬 회전을 부모 체인으로 합성
- **접지 그림자** — 모바일 성능을 위한 투영 블롭 방식

### 표면 질감

절차적 PBR 텍스처를 여러 레이어로 쌓아 "칠한 단색"이 아닌 실제 표면처럼 보이게 했습니다.

- **브러시드 메탈** — 가로로 늘어진 이방성 결
- **패널 심(seam)** — 함몰된 패널 경계 + 한쪽 모서리 베벨 하이라이트 → 가공된 판금 느낌
- **미세 스크래치** 수백 가닥
- **산화 얼룩** — 청동/녹 블룸이 메탈릭을 낮춤
- **크레비스 그라임** — 높이가 낮은 골에 때가 쌓여 AO가 깊어짐
- **에지 웨어** — 돌출 모서리만 금속이 벗겨져 밝고 매끈해짐
- 노멀맵 기복 3.0배 강도로 베이크

### 공격 예고 표시

단색 반투명 도형이 아니라 **전용 셰이더 모드 3종**으로 그립니다. 충전 진행도(0~1)가
그대로 시각화되어 "언제 터지는지"가 읽힙니다.

| 모드 | 사용처 | 표현 |
|---|---|---|
| 범위(disc) | 폭발·내려찍기·소환 | 중심에서 바깥으로 차오르는 필 + 해저드 스트라이프 + 맥동하는 외곽선 + 진행 경계의 스캔 링 |
| 레인(lane) | 돌진·직선 사격·빔 | 목표를 향해 흐르는 셰브런 + 양쪽 레일 + 선단(head) 하이라이트 |
| 경고 링(ring) | 좁혀오는 탄막·방사형 | 눈금이 새겨진 링 + 안쪽으로 조여드는 보조 링 |

### file:// 텍스처 문제와 해결 (중요)

Chrome은 `file://` 페이지에서 로컬 이미지를 **교차 출처**로 취급해서, 그 이미지를
`gl.texImage2D()` 로 GPU에 올리면 **SecurityError** 가 납니다. 이 경우 모든 표면이
대체 단색 텍스처로 그려져 **화면이 흰 네모 덩어리**가 됩니다.

해결: PBR 텍스처를 **data URI 로 JS에 내장**(`scripts/texture-data.js`, 61장 · 256px · 1.12MB)했습니다.
data URI 는 같은 출처라 업로드가 막히지 않습니다.

- `file://` 로 열면 → 내장 텍스처 사용 (더블클릭 실행 보장)
- `http(s)` 로 서빙하면 → `assets/textures/` 의 고해상도 원본 사용
- 원본 파일이 없으면 자동으로 내장본으로 폴백

## 적 6종 + 엘리트

각 적은 **실루엣만으로 구분되도록** 설계했습니다. 둥근 덩어리를 피하고 각진 프리즘·블레이드·
장갑 플레이트로 구성했으며, 가로세로 비율이 0.52~1.67로 크게 벌어집니다.

| 적 | 실루엣 | 행동 |
|---|---|---|
| **추적자** | 낮게 웅크린 곤충형. 앞으로 뻗은 블레이드 팔 + 뒤로 휘는 꼬리 가시 | 예고 후 돌진, 회복 시간 |
| **시간 사수** | 가늘고 높은 몸체에 한쪽만 달린 거대 포신 (강한 비대칭) | 거리 유지, 조준선 예고 후 발사 |
| **폭주 구체** | 매끈한 공이 아닌 각진 기뢰. 방사형 가시 8개 + 갈라지는 외피 | 접근 후 범위 예고 → 폭발 |
| **방패병** | 몸보다 큰 각진 타워 실드가 실루엣을 지배 | 정면 75% 감소, 측후면 약점 |
| **잔향 소환사** | 가장 길쭉한 부유체. 헤일로 링 + 늘어진 촉수 5가닥 | 하수인 소환, 순간이동 예고 |
| **궤도 감시자** | 가장 납작한 각진 자이로스코프. 삼각 스포크 + 기울어진 링 | 공전하며 방사형 탄막(안전 간격 보장) |

**엘리트 속성 3종**: 가속(붉은 시간 회로) · 분열(처치 시 2체) · 보호막(피해 감소)

## 최종 보스: 크로노보어

금이 간 거대한 시계 심장. 기계 팔 4개, 회전 고리 3중, 노출된 에너지 핵을 가진 대형 3D 모델입니다.

- **1단계 (100~65%)**: 부채꼴 투사체, 바닥 시간 균열, 느린 추적탄, 기계 팔 내려찍기
- **2단계 (65~30%)**: 연속 돌진, 회전 탄막, 이동 감속 지대, 외곽에서 좁혀오는 고리
- **3단계 (30~0%)**: 패턴 조합, 전장 공격, 소형 적 소환, 공격 속도 상승, **반격 가능한 그로기 구간**

모든 강공격은 바닥 예고(원/부채꼴/직선/고리)가 먼저 표시되고, 예고 범위와 실제 판정이 일치합니다.
충돌 판정은 보이는 크기보다 약간 작게 설정했습니다. 궁극기로도 즉사시킬 수 없습니다.

## 잔향 (런 중 업그레이드) — 19종

방을 완료하면 3개 중 1개를 선택합니다. 계열은 **잿불 / 폭풍 / 공허 / 중립**.

- **잿불**: 화상 부여, 화상 적 처치 시 폭발, 대시 경로 불길, 저체력 적 추가 피해, 스킬 적중 폭발
- **폭풍**: 연쇄 번개, 공격 속도, 대시 감전, 스킬 쿨다운 감소, 궁극기 충전량
- **공허**: 치명타 확률·피해, 생명력 흡수(상한 8%), 저체력 공격력, 처치 시 보호막
- **중립**: 최대 체력, 기본 피해, 이동 속도, 대시 쿨다운

희귀도는 일반 / 희귀 / 영웅. **시너지**: 같은 계열 3중첩 시 잿불(화상 +60%), 폭풍(5타마다 추가 번개),
공허(치명타 시 소량 회복)가 발동합니다. 카드에는 아이콘·계열·희귀도·현재 중첩·선택 후 수치·시너지
진행도가 표시되며, 모든 항목이 실제 전투 계산에 반영됩니다.

## 영구 성장 — 12종

런이 끝나면 **잔향 결정**을 받습니다(첫 방에서 죽어도 최소 보상 지급). 허브의 대장간에서 구매하며,
구매 즉시 저장되고 다음 런에 실제로 반영됩니다. 각 노드는 최대 레벨이 있어 무한 상승하지 않습니다.

최대 체력 · 기본 피해 · 이동 속도 · 대시 쿨다운 · 스킬 쿨다운 · 궁극기 충전 · 방 완료 후 회복 ·
시작 시간 파편 · 결정 획득량 · 잔향 새로고침 횟수 · 첫 잔향 희귀 확률 · **추가 생명 코어 해금**

## 사망 적응

마지막 사망 원인을 **근접 / 투사체 / 폭발 / 장판 / 보스** 5종으로 분류해 기록하고, 해당 적응을
자동으로 1단계 올립니다(각 최대 3단계).

- 근접·투사체·폭발·장판 적응: 단계당 해당 피해 **4% 감소**
- 보스 적응: 단계당 보스 대상 피해 **3% 증가**

결과 화면에 "이번 죽음을 잔향심장이 기억했습니다"와 획득 단계·효과가 명시되고, 다음 런의 실제
피해 계산에 적용됩니다. 죽음은 처벌이 아니라 성장의 일부입니다.

## 생명 코어

체력이 0이 되어도 생명 코어가 남아 있으면 1개를 소비해 **최대 체력의 50%로 부활**합니다.
약 1.5초 무적, 주변 적을 밀어내는 충격파, 바닥 에너지 고리, 부활 애니메이션이 함께 재생됩니다.
기본 1개이며 영구 성장으로 최대 2개까지 늘릴 수 있습니다.

## 저장

- `localStorage` 를 우선 사용하며 모든 읽기/쓰기를 `try/catch` 로 보호합니다.
- `file://` 등에서 저장이 막혀도 **메모리 저장으로 전환해 게임이 중단되지 않습니다**(안내 표시).
- 저장 항목: 저장 버전, 잔향 결정, 영구 업그레이드, 사망 적응, 선택 무기, 사망/승리 횟수,
  최고 기록, 최고 심연 단계, 설정, 튜토리얼 상태, 해금 정보, 진행 중인 런, 현재 seed
- **검증**: 잘못된 JSON, NaN/Infinity, 음수 재화, 잘못된 배열/문자열, 존재하지 않는 업그레이드 ID,
  범위를 벗어난 설정값, 손상된 진행 데이터를 모두 정규화합니다.
- `version` 필드와 마이그레이션 구조가 있습니다.

### 저장 내보내기 / 불러오기
타이틀 또는 허브의 **저장 관리**에서 저장 코드를 복사해 두었다가 붙여넣어 복원할 수 있습니다.
**저장 초기화**는 두 번 확인한 뒤 실행됩니다.

## 에셋 임포트 (CC0 3D 모델 넣기)

이 프로젝트는 **인터넷에서 에셋을 자동으로 받아오지 않습니다**(오프라인·file:// 실행 보장).
저작권 문제 없는 CC0 모델을 직접 받아 넣으면 게임용으로 변환·삽입됩니다.

추천 출처(상업 이용 가능, 직접 다운로드): Kenney.nl · Quaternius.com · polyhaven.com · opengameart.org(CC0)

```
1) assets/import/<이름>/model.obj (+ .mtl + 텍스처) 를 넣는다   (OBJ로 내보내기)
2) python3 tools/import_assets.py <이름> --as prop|weapon|char [--height 1.7]
3) index.html 에 한 번만 추가:
     <script src="scripts/mesh-data-imported.js" defer></script>
     <script src="scripts/imported-materials.js" defer></script>
4) 게임에서 EH.Meshes['<이름>'] 로 사용
```

변환기는 OBJ를 파싱해 (a) 노멀이 없으면 생성, (b) 와인딩을 게임 규칙에 맞게 교정,
(c) 발이 바닥(y=0)에 오도록 정규화·스케일, (d) 텍스처를 data URI로 내장(file:// 대응),
(e) 그룹별 재질을 등록합니다. `assets/import/testcrate/` 예제로 즉시 시험할 수 있습니다.

주의: 소품·무기·환경은 그대로 동작합니다. **캐릭터의 팔/다리 애니메이션**은 OBJ 그룹 이름이
리그 파트명(pelvis, torso, head, upperArmR/L, lowerArmR/L, thighR/L, shinR/L)과 일치할 때만
작동하고, 아니면 통짜로 움직입니다.

## 실제 제한사항

1. **실제 브라우저 플레이 검수는 여전히 수행하지 못했습니다.** 제작 환경에 브라우저가 없습니다.
   `file://` 조건을 시뮬레이션해 로더가 내장 텍스처를 선택하고 흰색 대체가 0건임은 확인했지만,
   화면에 그려진 실제 픽셀은 확인하지 못했습니다. `tests.html` 을 열면 실제 GL 에서 검증됩니다.
2. **내장 텍스처는 256px** 입니다. 원본(최대 1024px)보다 낮지만 캐릭터가 화면에서 100~150px 로
   보이므로 실사용에는 충분합니다. 정적 호스팅 시에는 자동으로 고해상도 원본을 씁니다.
3. **애니메이션은 GPU 정점 스키닝이 아니라 리지드 파트 계층** 방식입니다. 관절이 부드럽게
   늘어나는 변형은 없습니다.
4. **그림자는 shadow map 이 아니라 투영 블롭 접지 그림자**입니다.
5. 모델 폴리곤은 미드폴리(플레이어 1,036 / 보스 3,876 삼각형)입니다.
6. `assets/sprites/` (8.8MB) 와 `scripts/sprite-*.js` 는 이전 2D 실험의 산출물로 **현재 실행에는
   사용되지 않습니다**. 지워도 게임은 정상 동작합니다.

## 그래픽 모드

기본값은 **실시간 3D**(`spriteMode 0`)입니다. 캐릭터·적·보스·구조물 전부 실제 3D 메시를
관절 애니메이션과 함께 매 프레임 그립니다.

설정 화면의 **스프라이트 모드**를 `1` 로 두면, 같은 모델을 오프라인에서 구운 프리렌더
스프라이트로 대신 그립니다. 셀 셰이딩 톤이 더 강한 다른 룩이며, 성능상의 이점은 이제
없습니다 — 아래 최적화로 3D 경로가 같은 비용까지 내려왔기 때문입니다.

**드로우콜 예산 (최악 상황 = 적 14체 + 궁극기 발동, 상한 150)**

| | 3D | 스프라이트 |
|---|---|---|
| 최적화 전 | 267 | 121 |
| 재질 단위 관절 묶음 | 166 | — |
| 구조물 인스턴싱 | **121** | **94** |

두 가지가 컸습니다.

* **재질 단위 관절 묶음** — 파트마다 드로우콜을 쓰던 것을, 정점에 관절 인덱스를 심고
  파트 행렬을 `uParts[16]` 유니폼 배열로 한 번에 올려 **재질당 1콜**로 합쳤습니다.
  14파트 캐릭터가 3~6콜이 됩니다. 관절 스케일이 항상 균등해서(`Animator.compose`)
  법선 행렬은 회전 블록 정규화로 셰이더에서 유도합니다 — 별도 배열이 필요 없습니다.
* **구조물 인스턴싱** — 아레나 벽 링만 22개 복제라 프레임당 44콜이었습니다. 메시·재질·
  틴트가 같은 것끼리 묶어 `drawElementsInstanced` 한 번으로 그립니다. 불투명 지오메트리라
  순서가 바뀌어도 결과가 달라지지 않습니다.

## 단일 파일 배포

```
python3 tools/bundle.py            # dist/echoheart.html (1.5MB, 실시간 3D)
python3 tools/bundle.py --with-sprites   # 스프라이트 시트 포함 (5.3MB)
```

CSS·JS를 전부 인라인한 자립형 페이지를 만듭니다. 외부 요청이 하나도 없어 어디서든
그냥 열면 동작합니다. 기본 빌드는 구운 스프라이트 3.86MB를 뺍니다 —
`EH.SpriteImported` 가 없으면 `Game.spriteFor` 가 알아서 3D 경로로 떨어지므로
따로 막을 코드가 필요 없습니다.

번들러는 인라인한 모든 블록을 `node --check` 로 다시 파싱하고 DOM 요소 존재까지 확인한 뒤
통과해야만 파일을 남깁니다. 인라이닝은 소스 코드에 대한 문자열 수술이라
**HTML 로는 멀쩡한데 JS 가 깨진** 결과가 나올 수 있고, 실제로 한 번 그랬습니다
(`re.sub` 가 치환 문자열의 백슬래시를 해석해 JS 안의 `'\n'` 이 전부 실제 줄바꿈이 됐습니다).

재생성이 필요할 때:

```
python3 tools/generate_terrain.py both   # 바닥/벽 타일
python3 tools/bake_premium.py            # 캐릭터 시트 (여러 번 호출해 이어서 진행)
python3 tools/bake_props.py              # 구조물 빌보드
python3 tools/wire_sprites.py            # 데이터URI 임베드 + 메타 생성
python3 tools/embed_textures.py          # 지형 텍스처 임베드
```
